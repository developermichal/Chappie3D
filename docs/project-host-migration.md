# Project directories and agent data: safe host cutover

This procedure is **manual**. First stop the host agent and any clients writing to the old project directories. Never remove the old `volumes`, `data`, or `logs` directories as part of this cutover. Back up `data/projects.json`, `data/profiles.json`, `data/permissions.db`, `volumes`, and `logs` to a separate host disk; also back up any project folders previously opened in place (their `.chappie` files live in those folders). Record the project count and each project's `id`, `name`, `volume_name`, `root_path`, and `.chappie` checksum before changing configuration. Keep existing `session_history` fields in the copied registry: conversion to per-thread files belongs to the later thread-history migration.

1. Pick absolute, writable `CHAPPIE_DATA_PATH` and `PROJECTS_ROOT_PATH` directories on the Windows host, separate from the old `volumes` tree. Configure these in the agent's `.env`. Never open the data directory, its ancestors, or its descendants as a project. If `PROFILES_FILE_PATH`, `PROJECTS_FILE_PATH`, `PERMISSIONS_DB_PATH`, or `VOLUMES_BASE_PATH` are also configured, they **override** the matching derived paths; remove them or point them explicitly to the new host data location. The default `VOLUMES_BASE_PATH` is now `<CHAPPIE_DATA_PATH>/volumes` and must not point at the data directory itself. Existing unrelated paths in `data`/`volumes` remain untouched. Existing locally opened projects (`is_local_dir: true`) retain their original absolute `root_path` and `.chappie`; do not move them without explicit consent.
2. With writers stopped, copy `data/projects.json`, `data/profiles.json`, and `data/permissions.db` to the new data directory without overwriting existing files. Copy the old `volumes/sessions`, `volumes/live-chat`, and `volumes/generalcontexts` directories into the new data directory's `volumes` subdirectory, retaining all contents. Preserve the old logs and copy them to the new data directory's `logs` subdirectory if needed. If a target is already present, compare its contents before continuing; never use `-Force` to overwrite it.
3. For each old registry entry with `is_local_dir: false`, resolve `volume_name` under the old volumes root (reject names with separators or traversal), then **copy**, never move, the complete directory into a uniquely named directory beneath `PROJECTS_ROOT_PATH`. Reject symlinks in source and destination and abort on a collision rather than merging directories. If the copied folder has a legacy `.chappie/` directory, preserve it as `.chappie-legacy/` **inside the copy**, and create the new `.chappie` file from the copied `project.context` (if present) or the entry's `context_document`. Do not overwrite an existing `.chappie` file. Change only this registry entry's `root_path` to the new absolute path and `is_local_dir` to `true`; retain its project ID, profile ID, active session ID, history, and other metadata. Save the new registry using a temporary file in the same directory and an atomic replacement after every project has been verified. Do not write to the old registry.
4. Compare old/new registry IDs and counts, project file counts and checksums (including `.chappie-legacy` and source files), and inspect `.chappie` text in each migrated project. Check at least one file read and write through the agent API against a **copy** of a project, verify that a path outside that project is refused, and restart the agent using the new `.env`. Repeating these steps must skip entries already registered at their new root and abort on any source/destination discrepancy; never overwrite existing destinations to achieve a rerun.

This is a cutover **plan**, not an automatic migration command. The new runtime accepts a legacy registry but it does not silently copy old volumes or convert legacy histories. Keep the old snapshot available for rollback and do not point a newly configured host-data directory at a partially migrated registry. After verifying the cutover, migrate project session histories to per-thread files as a separate step, comparing the original history length and content with the new files before considering cleanup.
